# 다중 접속과 접근 제어를 지원하는 웹 서버 프로그램 작성
---

## Requirements
- 다중 접속 지원
    1. 클라이언트와 소켓 연결된 이후의 작업을 새로운 프로세스에서 수행하여 동시에 다수의 클라이언트가 접속할 수 있도록 지원
    2. 클라이언트와 접속 연결 및 해제 시 마다 클라이언트들의 정보를 아래와 같이 출력(이미지의 1)
    3. 10초에 한 번씩 연결되었던 클라이언트의 정보를 일괄출력(이미지의 2)
    4. 총 연결 횟수("Number of request(s)")는 서버 프로그램 실행 이후의 누적 값 유지
    5. 하단의 접속 기록은 최대 10개의 최근 기록만 출력(최신 시간 순서대로 정렬)
       <img width="257" alt="image" src="https://github.com/user-attachments/assets/129b0937-0bd3-4523-b78b-137156e52e96" />

- 접근 제어
    1. 미리 허용한 IP를 가진 사용자만 서버에 접속할 수 있도록 허가
    2. 현재 연결을 요청한 클라이언트의 IP를 기준으로 판단
    3. 접근 가능한 클라이언트의 목록을 파일("accessible.usr")로 유지
    4. Dotted-decimal 형태의 IP(ex.128.134.52.62)를 명시
    5. 10진수 수 대신에 *가 들어가 있을 경우로 처리
    6. 예시
- 허가되지 않은 IP에서 접속할 경우, 에러 메시지가 포함된 페이지 출력
    1. 허가되지 않은 IP(e.g. 128.134.52.62)가 웹 서버 (e.g. 128.134.52.61:44444)에 접근하고자할 때 접근 제한 메시지를 출력
    2. 해당하는 문자열을 전부 출력해야 함

## 고찰
fork 함수를 호출하고 자식 프로세스에서 client의 정보를 client_list에 저장 했었다. 이 상황에서 발생한 문제점은 fork 함수의 특성 때문이다. fork 함수는 현재 프로세스를 복제하여 새로운 프로세스를 생성하는데, 부모 프로세스와 자식 프로세스는 각각 독립된 메모리 공간을 가지기 때문에 자식 프로세스에서 저장한 정보는 부모 프로세스에서 사용할 수 없다. 그래서 read와 accept 후 값을 먼저 구한 후, 부모 프로세스에서 client 정보를 저장하는 방식을 사용했다. 이렇게 공유하는 변수를 사용하여 부모 프로세스에서 자식 프로세스에서 읽어들인 정보를 사용할 수 있도록 할 수 있었다.
